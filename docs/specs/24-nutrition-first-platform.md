# Nutrition-First Platform — Closing the Loop from Lens to Life

> Spec 23 shipped a deterministic Food Compass live lens (/food + /compass, deployed 2026-08-19). A four-reader / four-lens / synthesis audit on 2026-08-20 found the defining gap: **the lens is a one-shot scanner that throws away almost everything it learns.** `MealLogEntry.compassScore` is written on every log and consumed nowhere; the coach has zero food awareness; the home surface has no food presence; the glucose correlation ignores the score riding on its own input entries. This spec turns the lens into the spine of a nutrition-first platform by joining what already exists: sixteen features, almost all of them wiring, ordered so data integrity lands before the features that depend on it.
>
> **Status:** Authored 2026-08-20 from the adjudicated audit (owner approved all tiers), then **adversarially reviewed the same day** by four verification passes (code-anchor audit, cold-implementer red team, invariant/safety audit, dependency/completeness audit — 43 findings, all resolved into this revision). Code anchors verified against the working tree. Line numbers drift — re-locate by the quoted code.
>
> **The sixteen features** (the audit's tiers, recorded here so completeness stays auditable): quick wins — F2 correction chips, F8 FCS-band glucose insight, F7 post-meal nudge, F3 spoken size, F4 typed input in live voice, F6 Week in Food, F15 Spanish /compass; core bets — F11 Plate Builder, F10 daily totals, F9 last-time-you-ate-this, F12 coach food awareness; later — F12's Health Brief section, F13 why-this-score, F14 favorites/recents; audit-surfaced gaps — F1 meal-log integrity (edit/delete/retroactive time), F5 camera recovery, F16 label-photo fallback.

## Owner decisions (locked — do not re-litigate)

1. **All sixteen features ship.** Quick wins, core bets, "later" tier, and the audit's data-integrity gaps — the platform is pivoting nutrition-first. Phasing below is dependency order, not a cut line.
2. **Derivation over schema.** New UI reads existing state wherever possible. Schema touches are limited to: three optional `MealLogEntry` fields (F1), one new `foodFavorites` state field (F14), and one new `IdentifiedFood.source` value (F16). All migration-safe, optional, and a pre-existing save must never fail rehydration because of them.
3. **The plate average is a display derivation, not a score.** F11's calorie-weighted plate number is always labeled "plate average" and never presented — on screen or in voice context — as a published FCS for a food. Per-item scores remain the real numbers.
4. **The post-meal nudge is diabetes-lens-gated and dismissal is per-meal via sessionStorage** — no schema, no scheduler, no notification permission.
5. **/compass stays stateless, store-free, and input-shape-frozen.** It gains Spanish (F15) and nothing else — no text box (the page is camera + automatic voice by design; `e2e/compass.spec.ts:56` asserts the input's absence), no favorites, no personalization. The blank-state design from spec 23 F7 is untouched.
6. **Spoken-size mapping table** (F3): personal/small ≈ 0.75, medium/regular ≈ 1, large ≈ 1.5, extra-large/family ≈ 2 servings — always disclosed inline as an assumption with the stepper as the correction. No model estimation of portion. Parsed client-side from the utterance (see F3 — the identify `interpretation` never exists on /food).
7. **Glucose numbers are screen-only.** No feature hands the voice model a patient glucose/BP/A1C value to speak — the output guard (`src/ai/output-guard.ts`) hard-blocks "your blood sugar was NNN" utterances and latches the session. F9's paired reading renders on the facts card only.
8. **No new npm packages.** Everything here composes from existing deps.
9. **Deploy at the end to the existing Vercel project** (`vercel --prod --archive=tgz`; git push does nothing on this project). One commit per phase, path-scoped.

## Non-negotiable invariants (inherited from this codebase)

- **Deterministic numbers; the model identifies and narrates only.** Every number shown or spoken comes from the published table, the TS engine, or a deterministic derivation over stored state. AI context blocks carrying numbers are wrapped by `buildPerAskContext` (`src/ai/food-instructions.ts:160`) or the voice `buildContextMessage` (`src/hooks/use-food-voice-session.ts:237`), which append the exact existing wording **"Use the numbers above exactly; do not recompute them."** — `buildCompassContext` itself is the un-suffixed inner block those wrappers embed. New context content joins inside those wrappers. F16's label transcription is identification, not computation — the model reads printed digits; `computeLabelScore` does the math.
- **Safety gate everywhere.** All typed/voice AI turns go through `createSafeAiResponse` (`src/ai/safety-gate.ts`) or the voice gate + output-guard pair. `REALTIME_SESSION_CONFIG`'s `create_response:false` is load-bearing — typed live turns must go through `sendUserText` (which gates first), never a raw `response.create`. Nothing injected into context may bait the model into phrasing the output guard blocks (`specificNumberAssertions`, `output-guard.ts`) or `GROUNDING_SAFE_PHRASING` forbids (never state a specific BP/A1C/blood-sugar number).
- **Grounding and the wipe vector:** assistant messages cite source ids from `collectSourceFacts` (`src/ai/grounding-facts.ts`). On every load, `hasValidRelationships` (`src/state/storage.ts:253-260`) **rejects the entire persisted state — reset to demo — if any stored aiMessage cites an id not in `getKnownSourceIds`** (`storage.ts:175`). Any new citable id must therefore be in `getKnownSourceIds` UNCONDITIONALLY, independent of current state contents (F12).
- **localStorage only; no DB.** There is no prisma/ directory; do not create one. Persistence is a single key validated by **hand-rolled type guards + sanitizers in `src/state/storage.ts`** (not zod; the zod schemas in `src/domain/schemas.ts` are used at call sites like /food's log path). Migration safety has TWO steps: tolerant guards for optional fields, and — for any new top-level state field — a backfill in `loadStoredStateResult` (`storage.ts:1613-1642` sets each missing array to `[]` BEFORE validation). Miss the backfill and every pre-existing save resets to demo.
- **Null ≠ 0** in `NutritionFacts`. Sums over nutrition fields carry an "incomplete" marker when any contributing value is null — never coerce null to 0.
- **Snapshot-as-consumed convention** (this is the true basis rule; do not invent a stricter one): a `MealLogEntry.food` snapshot's nutrition is treated as the amount consumed regardless of `basis` — for `per_100g` FNDDS foods, one serving ≈ 100 g, the same assumption `computeFoodFlags` and `summarizeFoodGlucoseLink` already make; `portionServings` is the user's correction knob. F10/F11 sum snapshot values as-is; per-basis conversion is explicitly NOT attempted.
- **The FCS score is portion-invariant** — a property of the food, computed from the UNSCALED food (comment at `src/app/food/page.tsx:84-86`). Portions scale nutrition, flags, and day totals; they never touch the score.
- **Observational, never causal framing** for every correlation surface (F7/F8/F9): the `summarizeFoodGlucoseLink` message pattern ("an observation from your own logs, not a diagnosis") is the template.
- **i18n:** every new user-facing string lands in `src/i18n/strings.ts` in BOTH en and es. No hardcoded English in components (the existing `demoPreview` overlay violation gets fixed in F15).
- **No git worktrees.** Work directly on `master` in `C:\Patient centered`. Path-scoped commits (`git commit -- <paths>`), conventional messages, one commit per phase.
- Gates: `npm run check` (lint && unit && `next build` && bundle budgets), `npm run crisis:gate`, `npm run test:e2e` (Playwright starts its own dev server on port 3100 with `HEALTH_AI_PROVIDER=mock`; it shares `.next` — restart the preview server afterward, that is not your bug). Two pre-existing dr-screening e2e failures are known and unrelated.

## Features

**F1 — Meal-log integrity** (foundation; everything downstream trusts these entries):
- Extend `MealLogEntry` in THREE places — the type (`types.ts:228`), `mealLogEntrySchema` (`schemas.ts:88`), and the storage guard (`isMealLogEntry`, `storage.ts:424-435`) — with three optional fields: `servings?: number` (what the snapshot was scaled by; absent = 1), `mealId?: string | null` (groups plate items, F11), `editedAt?: string | null`. Guards tolerate absence (pre-existing entries stay valid). Write `servings` from `buildMealLogEntry` starting now.
- New store actions + reducer cases: `{type:"amendMealLogTime", entryId, loggedAt}` (sets `editedAt` to now) and `{type:"deleteMealLogEntry", entryId}`.
- `MealLogList` per-entry actions: **"I ate this earlier"** (choices: 30 min / 1 h / 2 h ago / custom `<input type="datetime-local">`, future times rejected) and **Delete** (two-tap confirm inline, no modal). Rationale on screen: post-meal pairing uses the logged time.
- Tests: reducer cases; schema round-trip with absent/present new fields; storage rehydration of pre-spec entries; future-time rejection.
- Why first: retroactive entries stamped "now" and un-deletable mistakes silently poison every correlation feature in P2–P4.

**F2 — Correction chips for camera matches on /food**:
- Add `candidates: {code, description, fcs}[]` to `LiveMatch` in `use-live-food-score.ts` (populate from the identify response; cap at 4 after dropping the matched code).
- Facts card renders "Not this? " chips for camera matches (source `fndds_lookup` only — never for barcode foods). Tap → POST `/api/food/identify` `{foodId: <bare code>}` (deterministic, free) → hook adopts the corrected match via a new `adoptMatch(match)` setter and **pins** it: vision results do not overwrite a pinned match for `CORRECTION_PIN_MS = 60_000` or until barcode preemption / `rearm()`.
- Pin lifecycle (all three specified, all fake-timer-tested): (a) a foodId response carries `candidates: []` — `adoptMatch` KEEPS the previous candidates list minus the adopted code, so the user can re-correct; (b) `adoptMatch` writes BOTH the match state and `stashRef`, so a barcode scan + clear within 60 s restores the corrected match, never the pre-correction one; (c) an idle auto-disarm during the pin keeps the pinned match on the facts card and shows F5's "Scan again" chip.

**F3 — Spoken size changes the numbers** (client-side; the identify `interpretation` never exists on /food — see anchors):
- Export a size parser from `food-order-intent.ts`: either export the existing `extractSize` or add `parseSpokenSize(text, language): Size | null` covering conversational en/es phrasings (reuse the existing size regexes; not just order syntax — "large pepperoni pizza" without "I'm ordering" must parse). New pure map `servingsForSize(size): number | null` per the locked table.
- In /food's existing portion effect (`page.tsx:258-281`, where `parsePortionServings` already runs over `latestPatientUtterance`): precedence is **numeric portion > spoken size > default 1**. When a size sets the portion, the facts card shows the inline assumption: "large ≈ 1.5 servings — adjust?" pointing at the existing stepper. Score untouched (portion-invariant); nutrition, flags, and F10 totals scale.
- /compass is unchanged: no portion UI there; size stays honestly listed in the "We heard" provenance's unmatched details (the published match genuinely does not represent it).
- Tests: numeric portion beats size; size beats default; "banana" (no size) leaves servings at 1; es phrasing.

**F4 — Typed input during live voice**:

**F10 — Daily running totals against the patient's lens limits**:

## Traps

1. **Meal snapshots are already scaled.** Day totals and plate sums read the snapshot as-is; multiplying by the `servings` field double-scales. `servings` is provenance, not a multiplier. F11 must scale at write time (`scaleNutrition(item.food.nutrition, item.servings)`) so this stays true.
2. **Plate average is not an FCS.** Never let the label, the voice context, or the brief call it a Food Compass Score; the per-item numbers are the published ones. F8's minimize-if-any bucketing rule is also NOT the plate-average band — two different rules, defined in two different places, on purpose.
3. **Correlation double-pairing:** without `mealId` grouping, a 3-item plate pairs one glucose reading three times. F8 groups both summarizers in the same commit; F6/F12 count grouped meals for floors and counts (per-item only for sums and averages).
4. **`page.tsx:73` placeholder fields** (`fcs1:0, nova:1, hsr:0, nutriScore:"C"`) — nothing new renders those, and `computeFullScore` never runs client-side (its context would swallow the fake nova).
5. **`IdentifiedFood.source` union lives in three places** (`types.ts:215`, `schemas.ts:79`, `storage.ts isFoodSource`) — miss the storage guard and rehydration silently drops F16 entries.
6. **`getKnownSourceIds` is a reset-to-demo vector, not just a grounding allowlist.** `hasValidRelationships` rejects the ENTIRE persisted state when any stored aiMessage cites an unknown id. The digest id goes in UNCONDITIONALLY; the storage test in F12 is the tripwire.
7. **Two glucose-number tripwires on voice:** the output guard blocks "your blood sugar was NNN" mid-utterance and latches the session; `GROUNDING_SAFE_PHRASING` forbids stating the number. Locked decision 7: glucose numbers are screen-only; voice context carries the non-numeric phrasing.
8. **Snapshot basis is MIXED and that's the convention:** per_serving (barcode/seed) and per_100g (FNDDS, 1 serving ≈ 100 g) snapshots sum as-is — the same assumption flags and the carb correlation already make. Do not attempt conversion; do not block sums on basis.
9. **Instructions build once per voice session** — weekly digest belongs in instructions; anything per-scan belongs in the camera context injection.
10. **Rearm must not raise spend:** `rearm()` re-enters the same throttled loop (2.5 s + scene gate); no extra timers. Provider-gate disarm stays terminal via the exposed reason.
11. **e2e vs dev server:** Playwright's own server on port 3100 shares `.next`; restart the preview server after e2e.
12. **Deploy ships all of master** — all gates green before `vercel --prod`; if anything unrelated fails, fix or surface, don't cherry-pick. Push does nothing (no GitHub auto-deploy).
13. **Catalog-freshness time bomb re-arms ~2026-09-19** (ladder catalogs): only relevant if this sprint drags into mid-September — run `node scripts/verify-catalog.mjs` + the human checks then; never widen the budget.
14. **sessionStorage nudge keys** are per-tab by design; don't "upgrade" to localStorage without a cleanup story.
15. **/compass stays off `useHealthState`** — F15 touches language only via the query param, never the store; the blank-state grounding contract (cite the synthetic carePlan.id) is unchanged; no text input appears.
16. **`foodId` means the bare FNDDS code at the API and in candidates; `food.id` is `fndds:<code>` in state.** F2/F9/F14 each say which form they use — mixing them returns `mode:"none"` and "features that mysteriously never match".
